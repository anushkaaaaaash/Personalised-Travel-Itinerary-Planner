# Private itinerary PDFs

- Retained plans: authenticated `GET /api/adaptive-plans/{id}/export` with `Accept: application/pdf`.
- Account archives: authenticated `GET /api/saved-adaptive-trips/{id}/export`, independent of temporary source expiry.
- Visible full snapshots: bounded, validated `POST /api/itineraries/export-pdf`; same application access boundary as itinerary generation, but **never invokes a provider or writes storage**.
- Existing text endpoint representation remains available for compatibility. User-facing downloads use PDF.

PDFs include dated days, timed activities and notes, daily outline, dining, dietary/accessibility/transport notes, daily expense categories and accepted whole-group totals. A partial plan is explicitly marked and missing days are not represented as completed. All pages are fetched and validated before returning a file; date gaps, cost mismatch, changed snapshot versions or size limits fail closed. Limits: 2 MiB serialized input corpus, 24 MiB output, 2,000 PDF pages and a cooperative 30-second rendering deadline checked between bounded flowables. Limits reject the entire download, never truncate it. All three export paths share a fail-fast single-export admission gate before fetching pages; a canceled request keeps its slot until its task actually finishes. The renderer also holds a single-thread semaphore and caps output buffer writes. Rendering runs off the async event loop. Snapshot POST has an explicit 128 KiB HTTP allowance; normal itinerary validation still caps its payload at 64 KiB. Other route body limits are unchanged. A disconnect does not forcibly kill a running native layout operation; the bounded background render can finish after the client leaves. These are cooperative safeguards, not an OS-level memory/CPU sandbox.

Privacy: no-store responses, fixed filenames, generic metadata, escaped text, no scripts/links generated from user input. Downloading does not save a trip. PDFs contain personal notes; review before sharing. The browser cancels/ignores results after sign-out, identity change, unmount, timeout, malformed PDF, size or length mismatch.

ReportLab 4.4.9 is pinned in requirements; CI already installs this file. Licensed DejaVu fonts ship with the renderer for stable Latin/Greek/Cyrillic text and many common symbols. CJK uses the standard Japanese CID font; rendering depends on the PDF viewer's CJK font support. Uncommon unsupported characters are shown explicitly as Unicode code points, not silently dropped. This is searchable/selectable text, not a screenshot; it is not currently a tagged PDF/UA document and complex-script shaping is not guaranteed.

Offline verification: `pytest tests/test_itinerary_pdf.py tests/test_adaptive_export.py`, frontend `adaptiveExport.test.js` and `itineraryPdf.test.js`. Local QA also rendered and extracted a 24-day / 31-page fixture, confirming all day headings and final activity-note markers plus accented Latin/CJK text. No paid calls or deployment required.
